# OpenOBB: báo cáo chốt kiến trúc tạm thời (sáng 2026-10-08)

## 1. Kết luận ngắn

- **Chưa vượt YOLO26 cùng cỡ.** Trên DOTA val (24 epoch, cùng dữ liệu, cùng ảnh 1024):
  - OpenOBB1-X đạt 75.6 mAP50, YOLO26x đạt 78.4 (kém 2.8).
  - Riêng mAP50:95 (độ khít của box) chỉ kém 0.8.
- **Tốc độ đạt yêu cầu:** OpenOBB1-X 20.0 ms/ảnh so với YOLO26x 12.8 ms, tức 64% FPS. Mục tiêu R3 là ≥ 60%.
- **Phần "thông minh" có tác dụng thật nhưng còn nhỏ:**
  - Nhánh vector đọc nét CAD giúp +0.8 mAP50 và **+2.5 mAP50:95** trên FloorPlanCAD.
  - Cửa đơn +3.6, bay-window +5.7, bàn +4.6, thang cuốn +6.3.
- **Đã tìm ra 2 nguyên nhân cụ thể của khoảng cách, và sửa được với chi phí thấp:**
  1. **Trần 300 query.** Ở cảnh đông xe/tàu, model hết chỗ để báo object. Chỉ tăng lên 600 khi suy luận (không train lại, không chậm hơn) đã cho +0.7 mAP50, riêng small-vehicle +6.3 vượt YOLO26s. Chưa áp dụng cho bản X.
  2. **So sánh chưa công bằng về augmentation:** YOLO train có mosaic, OpenOBB thì chưa. Mosaic là yếu tố chính giúp DETR hội tụ nhanh ở cùng số epoch (theo paper DEIM). Đã soạn thí nghiệm, chưa chạy.

## 2. Kiến trúc tạm chốt

```
Ảnh tile 1024 ──► HGNetv2 backbone ─► Hybrid encoder (AIFI + CCFM) ─► Decoder OBB (D-FINE xoay) ─► box xoay
                     (Apache-2.0, D-FINE)          ▲                    • rotated FDR: 4 cạnh + phân phối góc
                                                   │                    • sampling biến dạng theo góc
PDF/SVG vector ──► token nét ─► transformer ─► splat lên feature        • gán nhãn Chamfer + KLD, MAL IoU xoay
 (line/arc/...)    toàn bản vẽ   (2 lớp)      (khởi tạo 0)              • 600 query khi suy luận, không NMS
```

| Thành phần | Trạng thái | Bằng chứng |
|---|---|---|
| D-FINE chuyển sang OBB (decoder, loss, matching) | giữ | nền của mọi số liệu |
| RFS: lấy mẫu lặp class hiếm | **giữ** | +2.45 mAP50 (DOTA, S) |
| Nhánh vector (H7) | **giữ cho CAD** | +0.84 / +2.51 (FloorPlanCAD, S) |
| 600 query khi suy luận (H9) | **giữ** | +0.72, SV +6.3, latency không đổi |
| Context thumbnail toàn ảnh (H6) | **bỏ** | −0.18 rồi −3.88 |
| Head dense kiểu YOLO (H4) | tạm bỏ (có lỗi) | decoder −0.51; nhánh dense chỉ 49.8 |
| Strip context (H3) | bỏ | −0.13 |

## 3. Số liệu

### DOTA-v1.0 val (24 epoch, SS 1024/200, cùng điều kiện)

| Model | mAP50 | mAP50:95 | Latency (bs1, fp16, G4) |
|---|---|---|---|
| YOLO26x | **78.42** | **53.10** | 12.8 ms |
| **OpenOBB1-X + RFS** | 75.60 | 52.31 | 20.0 ms |
| YOLO26s | 74.77 | 49.49 | 8.9 ms |
| OpenOBB1-S + RFS, 600 query khi suy luận | 72.99 | 48.81 | 9.4 ms |
| OpenOBB1-S + RFS | 72.35 | 48.18 | 10.1 ms |
| OpenOBB1-S (gốc) | 69.89 | 46.13 | 9.4 ms |

So với YOLO26x, OpenOBB1-X:
- **Hơn ở** baseball-diamond +3.6, harbor +1.1, roundabout +0.3: các class lớn, cần ngữ cảnh.
- **Kém ở** small-vehicle −11.2 (trần query), helicopter −19.0 (cực hiếm, 72 mẫu), swimming-pool −5.7.

### FloorPlanCAD val (bản vẽ CAD thật, 30 class, 24 epoch)

| Model | mAP50 | mAP50:95 | Latency |
|---|---|---|---|
| YOLO26s | **78.51** | **70.54** | 7.8 ms |
| **OpenOBB1-S + RFS + vector** | 76.80 | 67.67 | 11.5 ms |
| OpenOBB1-S + RFS | 75.96 | 65.16 | 9.9 ms |

## 4. Đánh giá theo yêu cầu

| Mã | Yêu cầu | Hiện tại |
|---|---|---|
| R1 | Chính xác hơn YOLO cùng điều kiện | **Chưa đạt:** −2.8 (X, DOTA), −1.7 (S, FloorPlanCAD) |
| R2 | Hiểu ngữ nghĩa (vector, layer, text) | **Đã có phần đầu:** nhánh vector chạy được và có lợi; text/layer chưa làm |
| R3 | ≥ 60% FPS của YOLO cùng cỡ | **Đạt:** 64% (X); bản S 68–88% tuỳ dataset |
| R4 | Thương mại được | **Đạt:** code proprietary + phần Apache-2.0 (D-FINE); không Ultralytics; test chặn import |
| R5 | Benchmark trên dataset public | **Đạt:** DOTA-v1.0, FloorPlanCAD; DIOR-R đã có script |

## 5. Đề xuất bước tiếp (theo thứ tự lợi/chi phí)

| # | Thí nghiệm | Chi phí | Kỳ vọng |
|---|---|---|---|
| 1 | Eval lại checkpoint OpenOBB1-X với 600 query (không train) | khoảng 3 CU | +0.7 đến +1.5 (SV đang −11) |
| 2 | `e10-dota-mosaic-s`, `e10-fpc-vec-mosaic-s`: mosaic như YOLO/DEIM | khoảng 18 CU | DEIM báo cáo tăng rõ ở cùng epoch |
| 3 | Train với 600 query (thay vì chỉ suy luận) | khoảng 10 CU | thêm recall cảnh đông |
| 4 | Gộp các yếu tố có lợi lên bản X (DOTA và FloorPlanCAD), so YOLO26x | khoảng 75 CU | mục tiêu vượt YOLO26x |
| 5 | Sửa head dense (đang hỏng ở vật nhỏ), rồi thử hybrid | khoảng 10 CU | recall vật nhỏ kiểu YOLO; chưa ước được mức tăng |
| 6 | Nhánh vector: thêm text và layer khi chuyển sang PDF thật | code local | đúng chỗ AI_Takeoff đang lọc FP bằng luật tay |
